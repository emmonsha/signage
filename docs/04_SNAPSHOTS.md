# Снапшоты экранов (реальный кадр с плеера)

Функция делает **реальный снимок того, что в данный момент выведено на экран плеера**,
и сохраняет его. Это не реконструкция по данным сервера, а фактический кадр с устройства.

- Реализация: `snapshot.js` (HTTP-клиент + Digest/Basic), API и хранение — в `server.js`.
- UI: карточка «📸 Снапшот экрана» в `public/admin.html`.
- Тесты: `test/snapshot.test.js` (`npm test`, сеть не нужна).

## Архитектура и принятые решения

| Вопрос | Решение |
|---|---|
| Что такое снапшот | Реальный кадр с плеера через Local DWS |
| Доступ | Плееры в сети; адрес — ручная карта экран → IP в админке; логин/пароль DWS — в `.env` |
| Когда снимать | По кнопке в админке |
| Разрешение | Оригинал плеера |
| Хранение | История в томе, последние N кадров на экран |

Поток:

```
Админка ──POST /api/snapshot/<screen>──► Сервер
   Сервер ──POST http(s)://<player>/api/v1/snapshot──► Local DWS
   Плеер ──► { filename, width, height, ... }
   Сервер ──GET /api/v1/files/<filename>?contents&stream──► Плеер
   Плеер ──► JPEG/PNG ──► Сервер сохраняет в /storage/snapshots/<screen>/
```

Сервер сам ходит к плееру (исходящие HTTP-запросы), поэтому сервер и плееры должны быть
в одной доступной сети. Авторизация Local DWS — **Digest** (fallback Basic), как это делает
сам плеер.

## Настройка

### 1. Адрес плеера

В админке, в карточке экрана, поле «IP плеера»: `192.168.1.50`, `192.168.1.50:8080` или
`https://player.local:443`. Сохраняется в `data/players.json` (том `/storage`).

### 2. Логин/пароль DWS — в `.env`

```dotenv
PLAYER_DWS_USER=admin
PLAYER_DWS_PASSWORD=<пароль Local DWS>
PLAYER_DWS_SCHEME=http      # http | https
PLAYER_DWS_PORT=80          # 443 для https
SNAPSHOT_ORIGINAL=true
SNAPSHOT_KEEP=20                # сколько последних кадров хранить на экран
SNAPSHOT_TIMEOUT_MS=15000
```

Для конкретного экрана можно переопределить: `PLAYER_DWS_BIG_WALL_USER` /
`PLAYER_DWS_BIG_WALL_PASSWORD` (имя экрана в верхнем регистре, не-буквы → `_`).
Любая переменная поддерживает суффикс `_FILE` (Docker secrets):
`PLAYER_DWS_PASSWORD_FILE=/run/secrets/dws_password`.

Проверка, что DWS плеера отвечает (curl с Digest):

```bash
curl --digest -u admin:<пароль> -X POST http://<player-ip>/api/v1/snapshot
curl --digest -u admin:<пароль> \
  "http://<player-ip>/api/v1/files/sd/remote_snapshots/<filename>?contents&stream" -o shot.jpg
```

## API

Все маршруты требуют авторизации админки (кроме плеерных).

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/snapshot/players` | карта экран → адрес |
| POST | `/api/snapshot/players` | задать адрес: `{screen, address}` (пустой address — убрать) |
| POST | `/api/snapshot/:screen` | снять кадр с плеера и сохранить |
| GET | `/api/snapshot/:screen` | список сохранённых кадров (новые сверху) + `keep` + адрес |
| GET | `/api/snapshot/:screen/latest` | последний кадр картинкой (для `<img>`) |
| GET | `/api/snapshot/:screen/file/:name` | конкретный кадр |
| POST | `/api/snapshot/:screen/delete` | удалить кадр: `{file}` |

Примеры:

```bash
curl -s -b cookies -X POST localhost:3000/api/snapshot/players \
  -H 'Content-Type: application/json' -d '{"screen":"left","address":"192.168.1.50"}'
curl -s -b cookies -X POST localhost:3000/api/snapshot/left
curl -s -b cookies localhost:3000/api/snapshot/left
```

## Хранение

- Каталог: `STORAGE_DIR/snapshots/<screen>/`, имена файлов — ISO-время (сортировка по времени).
- Хранятся последние `SNAPSHOT_KEEP` кадров на экран, старые удаляются автоматически.
- Каталог `snapshots/` исключён из git (`.gitignore`) и лежит в томе `/storage` (попадает в бэкап).

## Если Local DWS под паролем

Сервер сам ходит к плееру, поэтому учётка DWS живёт **на сервере**, в `.env` (в поле «IP плеера»
админки пароль не вводится):

```dotenv
PLAYER_DWS_USER=admin
PLAYER_DWS_PASSWORD=<пароль локальной учётки плеера>
```

После правки — пересоздать контейнер, чтобы переменные подхватились:

```bash
docker compose up -d --force-recreate
```

Пароль локальной учётки плеера — **не** учётка FreeIPA/админки панели.
Для отдельного экрана можно задать свой: `PLAYER_DWS_BIG_WALL_PASSWORD=…`.
Пустой пароль допустим, если DWS без аутентификации.

## Диагностика

С 2026-11-25 сервер отвечает **подсказкой с действием**, а не сухим кодом; исходный текст
ошибки сохраняется в квадратных скобках в конце.

- **HTTP 401** — «проверьте `PLAYER_DWS_USER`/`PLAYER_DWS_PASSWORD` в `.env` … пароль
  от локальной учётки самого плеера, не от FreeIPA».
- **HTTP 403** — «выключен Local DWS или закрыт удалённый доступ».
- **HTTP 404 при скачивании** — «путь `remote_snapshots` на этой модели другой; проверьте поле
  `filename` из `POST /api/v1/snapshot` через curl».
- **ECONNREFUSED** — «проверьте IP и порт в поле „IP плеера“, а также что Local DWS включён».
- **ENOTFOUND** — «имя плеера не разрешается: укажите IP вместо имени».
- **Таймаут** — «сеть/файрвол или плеер занят; при медленной сети увеличьте `SNAPSHOT_TIMEOUT_MS`».
- В логе сервера — строка `Снапшот <screen>: <причина>`.

### Индикатор связи с плеером не зеленеет

Лампочка «🟢 онлайн» зависит **только** от heartbeat плеера и требует ссылку нового формата:

- **правильно:** `/player?token=<токен>` — из поля «🔗 Ссылка плеера» в админке;
- **устарело:** `/player?screen=<имя>` — такая ссылка heartbeat не проходит (сервер отвечает
  400), лампочка остаётся `⚪ Плеер ещё не подключался` / `🔴 Не�� связи с плеером`.

Проверка: в логе сервера при устаревшей ссылке появляется однократное предупреждение
«Плеер шлёт heartbeat СТАРОГО формата …». Откройте страницу плеера в обычной вкладке браузера —
там должно быть `?token=…`, а не `?screen=…`. Обновите адрес HTML5-виджета в системе публикации.

Поле «IP плеера» к лампочке отношения не имеет — это отдельная карта для снапшотов через DWS.

## Известные ограничения

- Нужен включённый Local DWS на плеере и сетевой доступ сервера к плееру.
- Поддерживаются Digest/Basic; DWS без аутентификации тоже работает (пустой пароль).
- Формат кадра — JPEG или PNG (как отдаёт плеер); размер ограничен только самим плеером.
- Снимается один кадр по кнопке; периодической/автоматической съёмки нет (по решению).
- Скриншот отражает текущий видеовыход; на некоторых моделях он может быть уменьшен до HD
  (зависит от `shouldCaptureFullResolution` и прошивки).


## Почему при нажатии «Снять снапшот» выкидывало на страницу входа

**Причина:** сессии админки жили в памяти процесса (`MemoryStore`), а контейнер при каждом
деплое/пересборке создаётся заново — сессии пропадали. Любой запрос после этого получал
**401**, а админка на 401 делает `location.reload()` → сервер отдаёт `login.html`.

Заметнее всего это было на снапшоте: он последний в цепочке (`POST /api/snapshot/:screen`
→ `loadSnaps` → `/api/status`), и шанс попасть на «мёртвую» сессию был выше.

**Исправлено:**
- `session-store.js` — файловое хранилище сессий на томе `STORAGE_DIR` (без новых
  зависимостей, атомарная запись `tmp`+`rename`, дебаунс 200 мс, сохранение по `SIGTERM`).
- `SESSION_SECRET` теперь хранится в `STORAGE_DIR/data/.session-secret` — cookie остаются
  валидными после перезапуска (раньше секрет генерировался случайно при каждом старте и
  обесценивал все сессии).
- `admin` на 401 больше не должен срабатывать «внезапно»: сессия живёт 12 часов и переживает
  пересборку контейнера.

**Проверено вживую:** вход → `docker compose up -d --force-recreate` → тот же cookie →
`/api/status` отвечает **200**, админка открывается, снапшот снимается.

## Баннер «плеер на устаревшей ссылке»

Если плеер шлёт heartbeat старого формата (`/player?screen=<имя>`), в карточке экрана
появляется предупреждение:

> ⚠ Плеер обращается по устаревшей ссылке. Последний раз: N мин назад с <IP>. Лампочка не
> зеленеет, потому что сервер принимает heartbeat только по токену. Скопируйте ссылку кнопкой
> «🔗 Ссылка плеера» и вставьте её в системе публикации вместо старой `/player?screen=…`.

Баннер исчезает сам, как только плеер пришлёт heartbeat по токену. Флаг `legacy` в
`/api/status` актуален 10 минут.
