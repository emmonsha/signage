# Управление экранами BrightSign

Админка + страницы-плееры (`left`, `right`, `big_wall`). Картинки, PDF и видео приводятся к 1920×1080 автоматически.

## Быстрый старт (Linux + Docker)

Нужны Docker Engine и плагин Compose v2 (`docker compose version`).

```bash
cp .env.example .env && chmod 600 .env       # Compose сам читает .env из этой папки
docker compose build

# 1. хэш пароля (скрытый ввод) -> вставьте строку в .env
docker compose run --rm --no-deps signage node hash-password.js

# 2. (рекомендуется) ограничьте админку своей сетью: ADMIN_ALLOWED_NETS=192.168.0.0/16 в .env

docker compose up -d
docker compose ps          # статус должен стать healthy
```

Админка: `http://IP_СЕРВЕРА:3000/admin`

Адреса для HTML5-виджетов в BrightAuthor:

- `http://IP_СЕРВЕРА:3000/player?screen=left`
- `http://IP_СЕРВЕРА:3000/player?screen=right`
- `http://IP_СЕРВЕРА:3000/player?screen=big_wall`

Закрепите IP сервера в роутере (DHCP reservation) — иначе после его смены презентации придётся перепубликовывать.

## Видео

Видео загружается так же, как картинка (кнопка «Добавить слайд»; форматы MP4, MOV, MKV, WebM, AVI и др.). Сервер сам конвертирует ролик через ffmpeg:

- контейнер MP4, видео H.264 High (уровень 4.2), `yuv420p`, 1920×1080, постоянная частота кадров (не выше `VIDEO_MAX_FPS`, по умолчанию 60), метаданные в начале файла (`faststart`);
- звук: по галочке «Оставить звук» AAC стерео 48 кГц, иначе дорожка удаляется;
- пропорции не 16:9: вписать с чёрными полями, обрезать по центру или отклонить (тот же выбор, что у картинок); вертикальные ролики и поворот из метаданных телефона обрабатываются;
- предупреждения при низком разрешении, частоте выше лимита, чересстрочном и HDR-видео.

Как это работает в админке:

- Время показа ролика равно его длине и не редактируется. Остальное (даты, порядок, удаление) как у картинок.
- Конвертация идёт в фоне по одному ролику (остальные в очереди), в карточке экрана виден раздел «Обработка видео» с прогрессом. Ролик попадает в эфир, когда готов; удаление отменяет конвертацию.
- Если сервер перезапустили во время конвертации, ролик помечается как прервавшийся: загрузите файл заново. Ошибка ffmpeg показывается в строке ролика.
- Видео нельзя поставить заглушкой, только картинку.

Ограничения и ресурсы:

- Конвертация нагружает процессор (ffmpeg запускается с пониженным приоритетом, но на слабом сервере поставьте `VIDEO_THREADS=2` и `VIDEO_PRESET=veryfast`). Минута 1080p занимает от десятков секунд до нескольких минут в зависимости от процессора.
- Контейнеру дано 2 ГБ памяти. Место на диске: размер файла после конвертации (обычно 5–15 МБ на минуту), оригинал удаляется.
- Через обратный прокси проверьте лимиты тела запроса: для nginx `client_max_body_size 2g; proxy_request_buffering off;` и увеличенные `proxy_read_timeout`/`proxy_send_timeout`. Сам сервер ждёт загрузку до 30 минут.
- **Проверьте воспроизведение на вашей модели BrightSign до боевого запуска**: потолок H.264 (профиль, уровень, 1080p60) зависит от модели плеера, а правила автозапуска и звука в HTML-виджете могут отличаться от браузера. Для более слабых моделей поставьте `VIDEO_MAX_FPS=30`. Сначала загрузите короткий тестовый ролик со звуком и без.
- Без Docker нужен ffmpeg в системе (`apt install ffmpeg` / `brew install ffmpeg`); без него картинки работают, а видео отклоняется с понятным сообщением. Пути можно задать через `FFMPEG_PATH` и `FFPROBE_PATH`.

## Безопасность

Три уровня, от простого к строгому:

1. **Хэш вместо пароля.** `ADMIN_PASSWORD_HASH` (scrypt, параметры OWASP) — в `.env` лежит не пароль, а его хэш. Открытый `ADMIN_PASSWORD` работает как запасной вариант, сервер предупредит в логе.
2. **Секрет в файле.** Вариант с Docker secrets (хэш читается из `/run/secrets/…`, не виден в `docker inspect` и переменных окружения):
   ```bash
   mkdir -p secrets && docker compose run --rm --no-deps signage node hash-password.js \
     | sed 's/^ADMIN_PASSWORD_HASH=//' > secrets/admin_password_hash
   chmod 400 secrets/admin_password_hash       # должен читаться uid 1000
   docker compose -f docker-compose.yml -f docker-compose.secrets.yml up -d
   ```
   Любой параметр поддерживает суффикс `_FILE` (`ADMIN_PASSWORD_HASH_FILE`, `ADMIN_PASSWORD_FILE`); файл имеет приоритет над переменной.
3. **Ограничение по сетям.** `ADMIN_ALLOWED_NETS=192.168.0.0/16,10.0.0.0/8` — админка, загрузка, удаление и статус отвечают 403 снаружи. Плееры продолжают работать: им открыты только `/player`, `/api/playlist/*`, `/uploads/*`, `/api/heartbeat`, `/healthz`.

Важно про ограничение по сетям:

- Это **второй рубеж**, основной — межсетевой экран хоста или прокси (`ufw`, `nftables`, правила роутера): закрывайте порт для чужих сетей там.
- С опубликованным портом Docker клиенты из LAN сохраняют свой реальный IP, а запросы с самого хоста приходят с адреса моста (`172.x.x.x`) — добавьте `172.16.0.0/12`, если заходите с сервера. В rootless Docker и Docker Desktop исходный адрес может теряться — там фильтруйте на прокси или файрволе.
- За обратным прокси задайте `TRUST_PROXY=1`, иначе сервер увидит адрес самого прокси. Прокси должен перезаписывать `X-Forwarded-For`, а не дописывать присланное клиентом.

## Потерян пароль

Хэш необратим: пароль не «вспоминают», а задают заново. Сброс делается **на сервере** (нужен доступ к docker), старый пароль не нужен:

```bash
scripts/reset-password.sh            # новый хэш -> .env
scripts/reset-password.sh --secret   # новый хэш -> secrets/admin_password_hash (если используете Docker secrets)
```

Скрипт дважды спросит новый пароль (ввод скрыт), посчитает хэш в контейнере, заменит `ADMIN_PASSWORD_HASH` в `.env` (забытый открытый `ADMIN_PASSWORD` тоже удалит, остальные настройки не тронет) и пересоздаст контейнер. Ошибка на любом шаге (пароли не совпали, слишком короткий) ничего не меняет. После сброса все прежние сессии админки закрыты.

Без Docker: `npm run hash-password`, замените строку `ADMIN_PASSWORD_HASH=` в `.env` и перезапустите сервер.

Почему сброс не «по почте»: у внутренней админки с одним пользователем нет надёжного второго канала, а письмо превращает доступ к чужому ящику в доступ к админке. Поэтому правило такое: пароль может сбросить тот, кто управляет сервером. Если потерян и доступ к самому серверу, это решается уровнем ниже: консоль виртуальной машины или гипервизора, физический доступ.

## Повседневное

```bash
docker compose logs -f signage         # логи
docker compose restart signage
docker compose down                    # остановить (данные сохраняются в томе)
git pull && docker compose up -d --build   # обновление кода
```

Контейнер сам поднимается после перезагрузки сервера (`restart: unless-stopped`; Docker должен быть включён: `systemctl enable docker`).

## Данные и бэкапы

Всё изменяемое хранится в томе `brightsign-signage_storage` (`/storage`: `data/` — плейлисты, `uploads/` — картинки).

```bash
scripts/backup.sh                      # -> backups/signage-ДАТА.tar.gz (хранится 14 последних)
scripts/restore.sh backups/signage-….tar.gz
```

Добавьте `scripts/backup.sh` в cron, например раз в сутки: `0 3 * * * /opt/signage/scripts/backup.sh`.

### Перенос данных с локальной установки (macOS и т.п.)

Ссылки на картинки в плейлистах относительные, поэтому папки `data/` и `uploads/` переносятся как есть:

```bash
docker compose up -d --build && docker compose stop signage
docker run --rm -v brightsign-signage_storage:/storage -v "$PWD/старая-папка":/src busybox:stable \
  sh -c 'cp -r /src/data /src/uploads /storage/ && rm -rf /storage/data/tmp && chown -R 1000:1000 /storage'
docker compose start signage
```

## Настройки (.env)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ADMIN_PASSWORD_HASH` | хэш пароля админки (рекомендуется) | — |
| `ADMIN_PASSWORD` | пароль в открытом виде (запасной вариант) | — |
| `ADMIN_ALLOWED_NETS` | сети, из которых доступна админка (CIDR через запятую) | без ограничений |
| `PORT` | порт на хосте | 3000 |
| `SCREENS` | имена экранов через запятую | left,right,big_wall |
| `MAX_PDF_PAGES` | максимум страниц в одном PDF | 50 |
| `MAX_VIDEO_MB`, `MAX_VIDEO_SECONDS` | максимальный размер и длина видео | 2048 МБ, 900 с |
| `VIDEO_MAX_FPS`, `VIDEO_THREADS`, `VIDEO_PRESET` | параметры конвертации (см. «Видео») | 60, авто, medium |
| `TRUST_PROXY`, `COOKIE_SECURE` | для работы за https-прокси (см. ниже) | выкл. |
| `SESSION_SECRET` | секрет сессий; нужен только для нескольких копий сервера | случайный при старте |

После изменения `.env`: `docker compose up -d`. Для хэша пароля есть `_FILE`-вариант (см. «Безопасность»).

## HTTPS через обратный прокси

Плееры BrightSign спокойно работают по http в локальной сети. Если админку нужно открыть по https (например, через Caddy/nginx/Traefik), проксируйте на `127.0.0.1:3000`, передавайте заголовки `X-Forwarded-For` и `X-Forwarded-Proto`, и задайте в `.env`: `TRUST_PROXY=1`, `COOKIE_SECURE=true`. Тогда вход по голому `http://IP:3000` перестанет работать — для плееров оставьте http-адрес в локальной сети или отдельное правило в прокси. Пример для Caddy:

```
signage.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

## Если что-то не так

- Контейнер перезапускается по кругу: `docker compose logs signage` — сервер пишет, что не задан пароль или неверен формат хэша или `ADMIN_ALLOWED_NETS`.
- `docker compose ps` показывает `unhealthy`: чаще всего том недоступен для записи.
- При использовании папки хоста вместо тома (`./storage:/storage`) выполните `sudo chown -R 1000:1000 storage`: контейнер работает от пользователя `node` (uid 1000).
- Секрет-файл не читается: он должен принадлежать uid 1000 или быть читаемым для него (`sudo chown 1000 secrets/admin_password_hash`).
- «Нужна авторизация» сразу после входа: включён `COOKIE_SECURE=true`, а вы открыли админку по http.
- 403 в админке: ваш адрес не входит в `ADMIN_ALLOWED_NETS` (в логе контейнера видно, какой адрес был заблокирован).
- Порт занят: измените `PORT` в `.env`.
